ConnectorX: LIMIT 0 for Schema Discovery

A Three-Line Fix That Touches Every Database — August 2026

LIMIT 0 for Schema Discovery

August 2026 · Giacomo Saccaggi · Issue #768

The Problem

ConnectorX needs to know the column names and types of a query result before it allocates Arrow buffers. To discover this schema, it runs the user's query with LIMIT 1 appended — fetching one actual data row just to inspect the column types, then discarding it.

This works, but it's wasteful. That one row might trigger a full table scan on some databases, or read from a slow remote storage layer. Most databases support LIMIT 0, which returns only the column metadata without touching any data pages.

The Fix

Three lines in connectorx/src/sql.rs:

// Before
q.limit = Some(Expr::Value(Value::Number("1".to_string(), false)));
format!("{} LIMIT 1", sql.as_str())
debug!("Transformed limit 1 query: {}", sql);

// After
q.limit = Some(Expr::Value(Value::Number("0".to_string(), false)));
format!("{} LIMIT 0", sql.as_str())
debug!("Transformed limit 0 query: {}", sql);

Impact

Affects schema discovery for: Postgres, MySQL, Trino, ClickHouse, BigQuery, SQLite, MSSQL. Oracle uses a separate function (WHERE rownum=1) and is unchanged — Oracle doesn't optimize LIMIT 0 the same way.

Why This Is Safe

LIMIT 0 is specified in the SQL standard and supported by all databases ConnectorX targets. The result set is empty (zero rows) but the column metadata (names, types) is always returned. This is exactly what ConnectorX needs for schema discovery.
